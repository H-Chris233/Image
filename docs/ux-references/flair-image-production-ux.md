# Flair.ai 图片生产交互体验对标

> 日期：2026-05-27
> 范围：只对标图片生产链路的交互体验，不展开商业化、企业 API、团队管理等外围能力。
> 参考对象：[app.flair.ai](https://app.flair.ai/) / [Flair.ai](https://flair.ai/)

## 1. 对标结论

Flair 的图片生产体验核心不是“用户填完参数后提交生成”，而是“用户在一个可视编辑器里组织产品、背景、模特、道具和输出格式，然后生成可用素材”。公开应用描述明确强调 visual editor、drag and drop、product photography。应用 bundle 中也能看到大量 `canvas`、`drag`、`drop`、`Product`、`Assets`、`Template`、`Background` 等交互语义，说明它的图片生产体验围绕画布、素材、模板和背景编辑展开。

AetherGenix 当前的图片生产链路已经有不少正确积木：品类向导、模板选择、AI 推荐、多选批量、进度阶段、抠图预览、格式选择、结果面板、下载和历史。但整体仍更像“配置表单 + 生成结果”，用户心智是“填表求图”。如果要对标 Flair，交互目标应该改成：“搭建一张商品图拍摄方案，并把结果沉淀成可复用的素材项目”。

## 2. 图片生产链路拆解

| 阶段 | Flair 体验范式 | AetherGenix 当前 | 差距 |
|---|---|---|---|
| 进入 | 直接进入视觉编辑器/产品摄影工作区 | 旧实现主要在 `/ecommerce`，当前目标入口为 `/create` | `/create` 需要承担“正在布置拍摄”的工作台感 |
| 添加商品 | 拖拽上传/放入画布，商品成为可操作资产 | 上传商品图，显示预览 | 商品只是输入，不是画布上的资产 |
| 选场景 | 模板/背景/资产与画布联动 | 模板网格选择，结果区提示 | 选中模板后没有即时画面反馈 |
| 调整画面 | 拖拽、组合、背景、道具、模特等可视控制 | 主要靠文本字段、比例和参数 | 用户操控感弱 |
| 生成 | 从当前画面/模板生成 | 点击生成，显示阶段进度 | 生成前缺少明确预期图 |
| 批量 | 多模板/多内容批量生产 | 已有多选模板和 `BatchResultPanel` | 批量入口还不够主路径化 |
| 编辑 | erase、upscale、variation、extend、regenerate 等工具围绕结果继续操作 | 有抠图、历史编辑、下载入口，但分散 | 缺少“生成后继续加工”的工具条 |
| 复用 | 资产、模板、自定义模型、项目持续复用 | 有历史、参考图、自定义模板 | 缺“商品项目/品牌资产”容器 |

## 2.1 实测观察：Explore 与 Create 入口

> 实测来源：用户在真实 Chrome 已登录 Flair 后提供的截图，页面 URL 为 `https://app.flair.ai/explore`。

Flair 登录后的 Explore 首屏不是空编辑器，也不是单一路径的生成表单，而是一个 workflow launcher。页面左侧是稳定导航，主区域标题为 `Generate with workflows`，以大卡片承载不同生产任务。

首屏可见工作流包括：

| 工作流 | 卡片文案 | 生产意图 |
|---|---|---|
| Generate On Model Photography | Generate on model fashion photography | 服装/模特商品图 |
| Generate Ad | Create custom ads with our graphic design engine | 广告图 |
| Generate Video | Transform images into stunning video content | 视频素材 |
| Generate Image | Generate an image from a text prompt | 文生图/普通图片 |
| Generate Image From Canvas | Generate images by arranging assets | 画布编排生成 |
| Train Custom Model | Train a custom model to generate images | 自定义模型训练 |

点击左侧 `Create` 后，Flair 不直接进入某个默认流程，而是打开一个大弹窗，标题是：

```text
What would you like to create?
```

弹窗左侧是生产类型导航：

```text
All
Product Images
Marketing & Ads
Product Videos
Human Model
```

弹窗右侧是 `Popular Workflows` 卡片。这个设计把“创建”拆成“先选择生产意图”，再进入具体工作流。它降低了用户面对复杂图像工具时的认知负担。

对 AetherGenix 的直接启发：

1. `/create` 不应该一上来就只有一个配置面板。
2. 应先提供电商图像生产工作流选择，例如商品场景图、广告图、白底图、素材包、画布生成、图片编辑。
3. `Create` 应该是“选择要创建什么”的入口，而不是“立刻打开一堆参数”。

## 2.2 实测观察：On Model Photography 上传引导

> 实测来源：用户点击 `Generate On Model Photography` 后提供的截图。

选中 On Model Photography 后，Flair 进入一个强引导上传页，顶部有绿色进度条，左上有 `Exit` 返回按钮，页面主标题为：

```text
Upload product images
```

副标题为：

```text
Upload images with multiple angles for better results
```

页面结构非常明确：

| 区域 | 作用 |
|---|---|
| 左侧 Example Images | 告诉用户什么样的输入图是合格的，展示多角度商品图与模特参考 |
| 右侧大上传区 | `Drag and drop image here or Choose file to upload` |
| 顶部进度条 | 暗示这是一个多步骤流程，不是一次性表单 |
| Exit 按钮 | 用户可以安全退出当前工作流 |

这个上传页有两个重要 UX 信号：

1. **先教育输入质量**：它明确告诉用户多角度图片会得到更好结果，并用示例图降低理解成本。
2. **上传区占主视觉**：页面几乎只做一件事，让用户先完成素材输入，而不是同时展示大量参数。

对 AetherGenix 的直接启发：

1. 商品图上传不应只是一个小 upload box，应成为工作流里的核心步骤。
2. 上传前应展示“推荐输入图示例”，尤其是白底图、多角度图、带包装图、细节图。
3. 对复杂工作流应使用进度条/步骤感，例如：上传商品 -> 选择用途 -> 选择场景 -> 生成素材包。
4. 对图片生产质量有影响的要求，应该在上传步骤直接解释，而不是藏在帮助文案里。

## 2.3 实测观察：上传后的 Generate Images 配置台

> 实测来源：用户在真实 Chrome 中上传商品图后提供的截图。

上传商品图后，Flair 进入 `Generate images` 页面。页面不是传统表单，也不是完全自由画布，而是一个左右分栏的生成控制台：

| 区域 | 内容 | UX 作用 |
|---|---|---|
| 左侧配置栏 | Product Category、Scene Description、Aspect Ratio、Number of Images、Human Models、Background | 让用户用少量结构化控件定义生成意图 |
| 右侧预览区 | 上传商品缩略图 + `Reimagine your product` 引导文案 | 给用户一个“当前商品即将被重构”的生成预期 |
| 底部 CTA | 大号 `Generate` 按钮 | 在配置完成后执行生成 |
| 右侧浮动箭头 | 上/下滚动或步骤导航 | 暗示配置区还有更多内容 |

关键观察：

1. **Product Category 是第一项**
   上传后系统默认分类为 `Other`，用户可以下拉选择品类。这说明 Flair 把品类作为生成策略的上游输入。

2. **Scene Description 自动生成**
   上传商品图后，Flair 自动生成一段场景描述，例如：

   ```text
   This is a consumer good, so I would arrange the valve in a visually appealing setting...
   ```

   这不是让用户从空白 prompt 开始写，而是让 AI 先给一个可编辑的拍摄方案。这个交互非常关键：用户看到的是“AI 已经理解商品并给出方案”，而不是“请你自己写 prompt”。

3. **Aspect Ratio 被套餐能力约束**
   截图中 Aspect Ratio 显示：

   ```text
   1:1 - Upgrade plan to modify
   ```

   免费/当前套餐下比例可见但不可改。这个设计既展示了能力，也把升级点放在具体控制项上。

4. **Number of Images 是显式数量选择**
   默认可选 `2` 或 `4`，并且选中态很强。图片数量不是藏在高级参数里，而是生成成本/产出数量的核心决策。

5. **Human Models 是可选素材轨道**
   配置区下方有 `Human Models`，包含 `Upload` 和多个预设人模缩略图。这说明 Flair 把“模特”作为生成素材的一类，而不是单独页面才有的功能。

6. **Background 是可选素材轨道**
   Background 区有 `Upload`、`None`、真实背景缩略图、纯色/渐变色块和横向更多入口。背景和人模一样，是围绕当前商品图的可插拔素材。

7. **右侧预览不是最终合成预览，而是生成意图预览**
   右侧大画布只显示商品缩略图和文案：

   ```text
   Reimagine your product
   Set your scene description, humans and background to generate
   ```

   它没有试图在生成前完整合成最终效果，但清楚告诉用户：当前要基于商品、场景、人模、背景重构结果。

对 AetherGenix 的直接启发：

1. 上传后应自动生成可编辑的 `Scene Description`，不要让用户从空白 prompt 开始。
2. 品类、场景描述、比例、数量、人物/模特、背景应组织成“生成策略”，而不是分散参数。
3. AetherGenix 现在已有模板、比例、数量、参考图、背景移除能力，可以重组成类似 Flair 的左侧配置栏。
4. 右侧预览第一阶段不必做到完整 canvas，只要清楚展示“当前商品 + 将被怎样重构 + 已选背景/人模/模板”。
5. 升级/额度限制可以直接嵌在具体控件里，而不是只在账单页或错误提示里出现。

## 3. AetherGenix 需要对齐的交互原则

### 原则 1：图片生产必须从“参数表单”转向“可视工作台”

当前用户在 AetherGenix 里主要看到的是模板、上传框、文本字段、格式、数量、模型、积分。对标 Flair 后，用户第一眼应该看到：

1. 中间是商品图生产预览区。
2. 左侧/顶部是商品资产和场景模板。
3. 右侧是精简参数和生成按钮。
4. 底部/右侧是生成结果与后续编辑动作。

不一定第一阶段就做复杂 canvas。可以先做“静态拍摄板”：

| 画面元素 | 第一阶段实现 |
|---|---|
| 商品图 | 上传后显示在预览区中心，可切换原图/抠图 |
| 背景模板 | 选中模板后预览区背景立即变化 |
| 平台比例 | 切换 1:1、4:5、16:9、9:16 时预览框同步变形 |
| 水印/Logo | 在预览区显示位置预览 |
| 文案/卖点 | 先显示占位布局，后续再做可拖动 |

### 原则 2：模板选择必须给即时反馈

Flair 的强体验来自“我还没生成，就知道大概会得到什么”。AetherGenix 当前 `TemplatePicker` 已经有真实缩略图、推荐角标、多选编号，这是好基础，但还缺两个动作：

1. 单击模板后，右侧主预览立即切换为该模板的场景预览。
2. 多选模板后，主预览显示“将生成 3 套场景”的小队列，而不是只在按钮上体现数量。

建议新增一个 `ScenePreviewBoard`：

| 输入 | 输出 |
|---|---|
| `productPreview` | 显示商品图 |
| `selectedTemplate` | 显示模板背景、风格标题、示例构图 |
| `aspectRatio` | 改变预览画幅 |
| `watermark` | 显示水印位置 |
| `selectedTemplateIds` | 显示待生成模板队列 |

### 原则 3：上传后自动进入“商品资产”状态

Flair 的产品摄影体验里，商品是素材资产。AetherGenix 当前上传后只是设置 `productImage/productPreview`，抠图需要用户理解并手动操作。建议上传后自动出现一个商品资产卡：

| 状态 | 交互 |
|---|---|
| 已上传 | 显示商品缩略图、文件名、替换、删除 |
| 正在抠图 | 轻量进度，不阻塞选模板 |
| 抠图完成 | 默认用透明底商品参与预览，保留“查看原图” |
| 抠图失败 | 降级使用原图，不挡住生成 |

这会让用户感知“系统已经帮我准备好了商品”，而不是“我还得找按钮处理图片”。

### 原则 4：生成后要提供“下一步编辑工具条”

Flair 的图片生产不是生成即结束，而是生成后继续变体、擦除、扩图、高清、替换背景。AetherGenix 的 `ResultPanel` 当前有预览、下载、再生成一次，但不够像生产流。

建议每张结果图悬停或选中后出现统一工具条：

| 工具 | 第一阶段动作 |
|---|---|
| 预览 | 打开 `ImagePreviewModal` |
| 下载 | 当前已有 |
| 再生成相似图 | 复用当前模板、商品、比例 |
| 换背景 | 回到模板选择并保留商品 |
| 高清 | 先放入口，后接 API |
| 擦除/局部重绘 | 先放入口，后接编辑接口 |
| 生成同款尺寸 | 复制当前图的 prompt 与商品，切换比例 |

### 原则 5：批量生成要变成默认路径，而不是高级功能

图片生产对标 Flair 时，“批量”不是加分项，而是主流程。AetherGenix 已有 `BatchResultPanel`，需要把入口前置：

1. 上传商品后自动推荐 3 个模板。
2. 默认选中推荐模板。
3. 主按钮文案改成“生成 3 套商品图”。
4. 结果按模板分组展示。
5. 支持一键导出全部。

这个改动比先做视频/真人模特更值得，因为它直接改善图片生产效率。

## 4. 建议的目标交互线

目标路径：从用户角度最多 4 步。

```text
1. 上传商品图
   -> 系统显示商品资产卡，并自动准备抠图预览

2. 选择用途/比例
   -> 主图、种草图、详情页横图、短视频封面

3. 选择或接受 AI 推荐场景
   -> 预览区即时显示构图预期

4. 点击生成素材包
   -> 按模板/比例分组出结果，可继续编辑、换背景、下载全部
```

交互重点：用户始终围绕“商品资产 + 预览板 + 结果素材包”移动，而不是在多个折叠区里找参数。

## 5. 推荐的信息架构

```text
/create
├─ 顶部：商品素材包 / 项目名 / 余额与预计消耗
├─ 左栏：商品资产
│  ├─ 上传/替换商品图
│  ├─ 原图/抠图状态
│  └─ 参考图/品牌资产
├─ 中央：ScenePreviewBoard
│  ├─ 画幅预览
│  ├─ 商品位置预览
│  ├─ 模板背景预览
│  └─ 文案/水印预览
├─ 右栏：生成控制
│  ├─ 用途/平台尺寸
│  ├─ AI 推荐模板
│  ├─ 模板多选
│  ├─ 数量/质量/模型
│  └─ 生成素材包 CTA
└─ 底部/右侧：结果与编辑
   ├─ 按模板分组
   ├─ 单图编辑工具条
   ├─ 生成相似图
   └─ 下载全部
```

## 6. 现有组件如何改造

| 现有组件 | 保留 | 改造方向 |
|---|---|---|
| `CreateFlowWizard` | 保留品类入口 | 作为 `/create` 内的新建商品图工作流引导；完成后回到 `/create` 工作台 |
| `TemplatePicker` | 保留缩略图、AI 推荐、多选 | 点击模板联动 `ScenePreviewBoard`，多选显示生成队列 |
| `FormatPicker` | 保留平台比例 | 移到主预览上方或右侧，让画幅切换即时可见 |
| `BackgroundRemovalPreview` | 保留抠图能力 | 上传后自动触发/展示为商品资产状态，不做孤立模块 |
| `GenerationProgress` | 保留阶段感 | 与具体结果卡绑定，批量时每个模板独立进度 |
| `ResultPanel` | 保留网格和下载 | 增加选中态与编辑工具条，结果按模板/用途分组 |
| `BatchResultPanel` | 保留批量结果 | 提升为默认结果面板，不只是附加块 |
| `WatermarkEditor` | 保留 | 接入主预览，实时显示水印位置 |

## 7. P0 可执行任务

### P0-1：新增 `ScenePreviewBoard`

验收：

- 上传商品后，中间预览区显示商品图。
- 选择模板后，预览背景/示例图立即变化。
- 切换 `FormatPicker` 后，预览画幅立即变化。
- 多选模板时，预览区显示待生成模板队列。

### P0-2：上传后自动商品资产化

验收：

- 上传完成后显示商品资产卡。
- 自动启动抠图或提供明显的一键抠图状态。
- 抠图失败不阻塞生成。
- 生成默认使用可用的最佳商品图版本：优先透明底，其次原图。

### P0-3：把批量生成做成默认 CTA

验收：

- 有 AI 推荐模板时默认选中 2-3 个。
- CTA 文案包含数量，如“生成 3 套商品图”。
- 预计消耗与余额展示在 CTA 附近。
- 结果按模板分组。

### P0-4：结果图增加生产工具条

验收：

- 每张图可执行：预览、下载、再生成相似图、换背景。
- 高清、擦除、扩图可先作为 disabled/coming soon，不阻塞主流程。
- 工具条在移动端可通过点选展开，不依赖 hover。

### P0-5：生成结果沉淀为商品项目

验收：

- 每次生成有项目名，默认用商品名/时间命名。
- 批量结果、单图结果、文案、导出配置都归属同一项目。
- 历史页可以按商品项目查看，而不是只看散图。

## 8. P1 体验增强

1. 拖拽式轻画布：允许移动商品位置、缩放商品大小。
2. 文案层：卖点文字可切换布局，生成广告图。
3. 背景替换：选中结果后直接替换模板生成变体。
4. 局部擦除：结果图上进入 mask 编辑，再提交局部重绘。
5. 套图模式：同一商品一次产出主图、社媒图、banner、详情页首屏。

## 9. 不建议现在做的事

| 暂缓项 | 原因 |
|---|---|
| 完整 Figma/Canva 式自由画布 | 工程量大，容易拖慢核心生成效率 |
| 真人模特全链路 | 重要但不是图片生产体验 P0；先把商品图工作台打顺 |
| 视频生成 | Flair 有，但会拉开模型和成本复杂度 |
| 企业团队协作 | 图片生产交互尚未定型时，不宜先做组织层 |
| 复杂自定义模型训练 | 可以先用品牌资产/模板复用替代 |

## 10. 一句话 UX 目标
