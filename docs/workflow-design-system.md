## 一、设计理念（3 条核心原则）

### 原则 P-1：结果先行，配置后置

> **"Show the output before you ask for the input."**

用户来 AetherGenix 的目的是看到生成结果，而不是填写表格。每一个工作流页面，必须在用户完成任何配置之前，就让他看到「用这个工具能产出什么」。

| 一流工具怎么做                                        | 效果                 |
| ---------------------------------------------- | ------------------ |
| Ideogram：中央文本框下方铺满社区作品，页面打开即看到数百张真实生成图         | 用户进入页面 0 秒内建立了信心   |
| Pebblely：模板缩略图是真实商品合成效果图，而非抽象色块                | 用户点选时已经知道结果大概是什么样的 |
| Midjourney Explore：Explore 页面作为冷启动缓冲区，展示顶级社区作品 | 消除「我不知道能生成什么」焦虑    |

**对应的 AetherGenix 反例：**  
电商页模板缩略图是 CSS 渐变色块，用户无法从「深棕色渐变」推断出「室内生活场景图」会是什么效果。

**执行要求：**

- 每个垂类页面的首屏必须有至少 **4 张真实生成效果示例**（非 UI 占位符）
- 模板/风格选择器的缩略图必须是**真实生成结果**，不得使用纯色或抽象渐变
- 空状态必须展示「这个场景能产出什么」，而非展示「如何填写表单」

---

### 原则 P-2：上传即响应，输入即可见

> **"Every user action must produce an immediate visible reaction."**

AI 生成有延迟是正常的，但「上传文件」「选择模板」「切换格式」这类瞬时操作不应该有视觉上的沉默期。用户的每一个动作都必须在 **300ms 内产生可见的 UI 变化**。

| 一流工具怎么做                                                             | 效果                     |
| ------------------------------------------------------------------- | ---------------------- |
| Photoroom / Remove.bg：图片上传完成的瞬间，AI 就开始处理并显示进度——用户感知不到「上传」和「处理」之间的分隔 | 心理上认为系统极快              |
| Krea.ai：画布上每一次笔触都触发实时推理，结果画面同步流式刷新                                  | 创作过程变成了「实时雕塑」而不是「提交任务」 |
| Pebblely：选中模板后，右侧预览框立即更新（用商品 placeholder 合成进场景）——不需要提交              | 用户在决策前就能看到大致效果         |

**对应的 AetherGenix 反例：**  
上传商品图后，UI 静止——没有抠图预览，没有 AI 分析反馈，没有「下一步」提示。用户不知道系统是否收到了图片。

**执行要求：**

- 上传图片后必须在 **300ms 内** 显示缩略图预览（已有），并在 **1s 内** 开始任何形式的 AI 分析反馈（skeleton / 进度 / 建议）
- 模板切换、格式切换、数量切换必须有即时视觉响应（选中态动画、预览更新）
- 生成过程必须有分阶段进度反馈（已有 GenerationProgress，可作为全产品标准组件）

---

### 原则 P-3：最短路径优先，高级选项渐进披露

> **"The first result should be reachable in the fewest possible decisions."**

从「打开页面」到「看到第一张生成结果」，所需的决策数量直接决定了转化率。对标数据显示，一流工具在 **1~2 步**内出首张结果；AetherGenix 电商页当前需要 **7+ 步**。

| 一流工具的步骤对比（benchmark 数据）                            |
| -------------------------------------------------- |
| Ideogram / Krea / Lovart / 豆绘AI（通用）：**1 步**        |
| Midjourney / Pebblely / 豆绘AI（电商）/ Leonardo：**2 步** |
| 万相营造：**2~3 步**                                     |
| **AetherGenix 电商（当前）：7+ 步**                        |

**执行要求：**

- 每个垂类页面必须定义「最短路径」：从页面打开到首张结果，**必填操作 ≤ 3 步**（见 Step Budget）
- 所有非必填参数（材质描述、卖点文案、高级质量选项等）必须**默认折叠**
- UI 层级：主操作（唯一）> 辅助操作（按需展开）> 高级选项（专家模式，深度隐藏）
- 「快速上手路径」与「精细配置路径」必须共存，不强制用户二选一

## 二、工作流范式分类与选型指南

### 2.1 五种范式定义

| 范式 ID  | 名称                | 核心心智模型             | 用户第一步      | 最优步骤数 |
| ------ | ----------------- | ------------------ | ---------- | ----- |
| **P1** | Prompt-First      | "用语言召唤图像"          | 看到文本框，输入描述 | 1     |
| **P2** | Upload-First 即时结果 | "上传即得到处理结果"        | 拖拽/点击上传    | 1     |
| **P3** | Template-First    | "选模板，素材放进去"        | 浏览模板，选择风格  | 2     |
| **P4** | Canvas-First 实时   | "所见即所得创作台"         | 画布上落笔/操作   | 1     |
| **P5** | Agent 对话式         | "告诉 AI 想要什么，它全权完成" | 发送一条自然语言消息 | 1     |

### 2.2 选型决策树

```
开始：判断这个垂类的核心用户价值是什么？
│
├─ 用户有明确的创意想法，需要 AI 实现
│  └─ 目标用户是创意人/设计师？
│     ├─ 是 → P1 Prompt-First（参考：/create 通用生图页）
│     └─ 用户需要实时反馈？ → P4 Canvas-First（未来高端模式）
│
├─ 用户有一张现成图片需要处理/增强
│  └─ 处理结果是单一、确定性的（抠图/换背景/增强）？
│     ├─ 是 → P2 Upload-First 即时结果
│     └─ 否（需要选风格/场景）→ P3 Template-First
│
├─ 用户需要为商品/产品生成营销图
│  └─ → P3 Template-First（参考：/ecommerce 电商场景）
│     可以 + P2 混合：上传商品图后即时抠图（P2 响应），
│     然后进入模板选择（P3 主流程）
│
├─ 用户需要完整的品牌/设计资产集
│  └─ → P5 Agent 对话式（参考：Lovart 模式）
│     适合：品牌套件、营销物料全套、详情页整体设计
│
└─ 用户需要批量处理大量商品图
   └─ → P3 Template-First + 批量扩展
      重点：一次配置，多商品/多模板批量执行
```

### 2.3 AetherGenix 现有页面范式归属

| 页面           | 当前范式                  | 目标范式                         | 状态      |
| ------------ | --------------------- | ---------------------------- | ------- |
| `/create`    | P1 Prompt-First（基本正确） | P1（优化提示框权重 + 内联结果）           | 🟡 部分符合 |
| `/ecommerce` | P0 表单驱动（不在 5 种范式内）    | P3 Template-First + P2 上传即响应 | 🔴 需重构  |
| 未来：白底图       | —                     | P2 Upload-First 即时结果         | ⬜ 待建    |
| 未来：服装试穿      | —                     | P2 + P3 混合                   | ⬜ 待建    |
| 未来：品牌套件      | —                     | P5 Agent 对话式                 | ⬜ 待建    |

## 三、通用设计模式库

每个模式遵循统一格式：**名称 / 适用场景 / 结构 / 实现要点 / 反例**。

---

### Pattern 1：结果前置面板（Result-First Panel）

**适用范式：** P1 / P3 / P5  
**适用场景：** 所有有「生成区域」的工作流页面

**结构：**

```
┌─────────────────────────────────────────────────────┐
│  [结果展示区] ← 初始状态：展示4~6张示例图（带"示例"水印）    │
│  [生成后：内联替换为真实结果，瓦片网格，可点击放大]          │
└─────────────────────────────────────────────────────┘
┌──────────────┐
│  [配置区]    │
│  [生成按钮]  │
└──────────────┘
```

**布局规则（宽屏 lg+）：** 配置区（左/上，固定宽度）+ 结果区（右/下，弹性），比例约 2:3  
**布局规则（移动端）：** 配置区折叠为顶部抽屉，结果区占满视口

**实现要点：**

- 初始状态展示示例图（**必须是真实 AI 生成图，不得是设计稿截图**）
- 生成中：结果区显示 skeleton（保持布局稳定，不跳动）
- 生成完成：结果图内联替换 skeleton，**不跳转到任何其他页面**
- 结果图可直接在区域内点击放大（lightbox），下载按钮悬停显示

**反例：** 生成完成后将结果放入「历史记录」标签页或独立抽屉，用户需要切换视图才能看到。

---

### Pattern 2：上传即响应（Upload-Trigger Feedback）

**适用范式：** P2 / P3（含上传步骤的所有范式）  
**适用场景：** 任何包含图片上传的工作流

**时序规范：**

```
用户拖拽/点击上传
   ↓ 立即（< 100ms）
显示文件名 + 上传进度条
   ↓ 上传完成（< 1s 通常）
显示缩略图预览 ← 已实现 ✅
   ↓ 同步触发（< 500ms 内开始）
AI 分析阶段（显示 skeleton 分析状态）：
  - 检测商品类别（可选展示："检测到：护肤品瓶"）
  - 自动抠图预览（透明背景 + checkerboard 图案）
  - 推荐适合的模板（高亮 1~3 个推荐模板）
```

**实现要点：**

- 上传完成的视觉确认不依赖用户主动操作（不能只有缩略图，还需要系统确认反馈）
- 如果 AI 分析需要 2s+，显示带文字的 skeleton（"正在分析商品类型…"），不能静默等待
- 分析结果以「建议」形式呈现，不强制覆盖用户的选择

**反例：** 上传图片后 UI 完全静止，用户无法判断上传是否成功，也不知道下一步是什么。

---

### Pattern 3：渐进式配置（Progressive Disclosure Config）

**适用范式：** 所有范式  
**适用场景：** 任何有超过 3 个配置项的工作流

**三层配置结构：**

```
第 1 层（必填/核心，永远可见）：
  ├─ 上传区 / 主输入框（唯一主操作）
  └─ 模板/风格选择（P3 必须；P1 可选）

第 2 层（常用，一键展开）：
  ├─ 格式/比例选择
  ├─ 数量 chip
  └─ 简要描述（1 行）

第 3 层（高级，默认折叠）：
  ├─ 材质/卖点/场景描述
  ├─ 图片质量/分辨率
  └─ 参考图上传
```

**实现要点：**

- 第 2 层的展开按钮放在第 1 层配置下方，**不遮挡主流程**
- 「高级选项」展开时使用动画（高度渐变，duration 200ms），避免内容跳动
- 首次进入页面时，确保用户仅看到「第 1 层」就足以完成一次生成（满足 Step Budget）
- 用户展开过「高级选项」后，记忆状态（用 localStorage），下次进入保持上次的开合状态

**反例：** 所有配置项默认全部展示，包括「材质描述」「卖点文案」「参考图」等低频字段——电商页当前现状。

---

### Pattern 4：内联结果替换（Inline Result Replacement）

**适用范式：** 所有范式  
**适用场景：** 生成结果展示

**状态机：**

```
[空/示例状态] ──提交生成──→ [Skeleton 加载状态]
                                     │
                               生成完成 ↓
                         [结果网格状态] ──点击单张──→ [全屏预览状态]
                                │
                         重新生成 ↓
                         [Skeleton 加载状态]（结果区原地刷新）
```

**实现要点：**

- **绝对不跳转**：结果永远在当前页面的结果区内展示，零导航开销
- Skeleton 的格子数量与请求的生成数量一致（用户设置 4 张，就显示 4 个 skeleton）
- 每次新生成的结果**置顶**（不追加到历史底部），用户无需滚动
- 结果图片上悬停显示操作按钮：下载、编辑（跳转编辑器）、「基于这张重新生成」
- 历史图以轻量「最近结果」条折叠在结果区下方/侧，不占主视口空间；全量历史归 `/assets`，结果区只保留最近若干张作高频回填入口（回填即时生效，不跳转）

**反例：** 生成完成后结果进入任务抽屉，然后再出现在页面底部的历史记录区，用户需要 2 次额外操作才能看到结果。

---

### Pattern 5：空状态引导（Empty State Inspiration）

**适用范式：** 所有范式  
**适用场景：** 页面首次进入 / 尚无历史结果时的结果区

**内容要求（三选一，优先级递减）：**

1. **最优：真实用户生成案例**（如有社区功能，展示真实历史作品，带用户名）
2. **次优：真实 AI 生成演示图**（由产品团队用真实商品图生成，**不加水印，不打"示例"标签**）
3. **保底：带说明的占位符**（展示 4~6 个卡片，每张显示商品类型名称 + 预期效果描述）

**禁止使用：**

- 设计稿截图或 Photoshop 合成图冒充 AI 生成效果
- 空白状态仅展示「如何使用本工具」的文字说明（流程图、步骤列表）
- 仅展示品牌 logo + 一句 slogan

**附加机制：「用示例商品体验」入口**  
在上传区旁提供一个「用示例商品试试」按钮，点击后加载预置商品图（由产品团队准备 3~5 张不同品类），让首次用户无需自备图片即可体验完整流程。

---

### Pattern 6：生成进度反馈（Generation Progress Feedback）

**适用范式：** 所有含 AI 生成的范式  
**适用场景：** 任何需要等待 AI 处理的阶段（通常 5s+）

**标准组件：GenerationProgress**（已实现于 `/src/components/ecommerce/GenerationProgress.tsx`）

**阶段定义规范（按垂类定制）：**

| 垂类    | 阶段 1 | 阶段 2 | 阶段 3 |
| ----- | ---- | ---- | ---- |
| 电商场景图 | 商品识别 | 场景构建 | 精细渲染 |
| 通用生图  | 理解描述 | 构图生成 | 细节优化 |
| 白底图   | 图像分析 | 背景移除 | 边缘精修 |
| 服装试穿  | 服装识别 | 人体匹配 | 效果合成 |

**实现要点：**

- 阶段文字必须是**动词短语**，让用户感知 AI 正在工作（「商品识别」比「处理中」好）
- 最后一个阶段设置超长 duration（99999ms），等真实完成信号再切换到完成状态
- 生成完成时，进度组件淡出（opacity 0，duration 300ms），结果图淡入（opacity 1，duration 400ms）

## 四、步骤数预算（Step Budget）

### 4.1 定义：什么算"1 步"

> 1 步 = 用户做出 1 个有意识的决策并执行 1 个操作。

| 算 1 步                | 不算步骤（系统自动完成）      |
| -------------------- | ----------------- |
| 上传图片（打开文件选择器 + 选择文件） | 图片上传后显示缩略图        |
| 选择一个模板               | AI 分析上传的图片        |
| 点击「生成」按钮             | Skeleton 动画       |
| 在文本框输入描述 + 回车        | 格式/数量保持上次设置（记忆状态） |

### 4.2 各垂类步骤预算

| 垂类                 | 范式      | 快速路径目标（≤ N 步） | 完整配置路径（步骤上限） | 当前状态    |
| ------------------ | ------- | ------------- | ------------ | ------- |
| `/ecommerce` 电商场景图 | P3 + P2 | **≤ 3 步**     | ≤ 6 步        | 🔴 7+ 步 |
| `/create` 通用生图     | P1      | **≤ 2 步**     | ≤ 5 步        | 🟡 ~3 步 |
| 白底图（未来）            | P2      | **≤ 1 步**     | ≤ 3 步        | ⬜       |
| 服装试穿（未来）           | P2+P3   | **≤ 2 步**     | ≤ 5 步        | ⬜       |
| 品牌套件（未来）           | P5      | **≤ 1 步**     | ≤ 3 步        | ⬜       |

### 4.3 电商页快速路径设计（目标 3 步）

```
步骤 1：选择场景模板
         ↓ 系统自动：高亮上传区，显示「下一步：上传你的商品图」
步骤 2：上传商品图
         ↓ 系统自动：抠图预览（~1s），格式默认 1:1，数量默认 1
步骤 3：点击「生成场景图」
         ↓ 系统自动：内联显示 skeleton → 结果图
─────────────────────────
用户已得到第一张结果。后续迭代（调格式/换模板/改数量）
均在已有结果的基础上进行，不重新开始流程。
```

### 4.4 步骤预算审计方法

新开发垂类页面时，在交互评审前执行：

1. 从「打开页面」开始，用手指点击模拟真实用户操作
2. 记录每次「有意识的决策 + 操作」的次数
3. 确认满足对应垂类的快速路径目标
4. 如果超标：找出哪些步骤可以合并（如：上传+选模板同时触发预览）或自动化

## 五、页面布局规范

### 5.1 标准双栏布局（Desktop lg+）

```
┌────────────────────────────────────────────────────────┐
│  [页面标题区] 垂类名称 + 简短说明（1 行）               │
├──────────────────────┬─────────────────────────────────┤
│                      │                                 │
│   [配置面板]         │   [结果展示区]                  │
│   ─────────          │   ─────────────                 │
│   • 主输入/上传区    │   • 初始：4~6 张示例图           │
│   • 模板选择器       │   • 生成中：Skeleton 网格         │
│   • 第 2 层选项      │   • 生成后：结果图网格            │
│   • 高级选项(折叠)   │   • 历史记录(折叠区)             │
│                      │                                 │
│   [生成按钮]         │                                 │
│   [进度条]           │                                 │
│                      │                                 │
│   宽度: 320~400px    │   宽度: flex-1（最小 480px）     │
│   (lg: w-[360px])    │                                 │
└──────────────────────┴─────────────────────────────────┘
```

**CSS 骨架：**

```
grid-cols-1 lg:grid-cols-[360px_1fr]
gap-6
items-start
```

```css
  min-height: 480px; /* 约等于 4 张 2:1 缩略图 + 间距 */
}
```

## 六、反模式清单

以下 8 种模式被明确识别为用户体验杀手，基于 benchmark 数据和 AetherGenix 用户旅程分析。**任何新垂类页面不得包含这些模式。**

---

### ❌ Anti-Pattern 1：表单驱动（Form-First）

**描述：** 页面主要内容是一组输入表单，用户必须填完表单才能触发生成。  
**为何有害：** 用户的心理模型是「我想看效果」而不是「我想填表格」。表单制造认知负担，直接降低启动率。benchmark 数据：所有一流工具均无表单驱动流程。  
**如何修正：** 将文字输入改为「提示词参考」可选项；必填信息通过上传图自动推断；其余用渐进式配置（Pattern 3）处理。

---

### ❌ Anti-Pattern 2：结果跳转到独立视图

**描述：** 生成完成后，结果显示在与配置区不同的标签页、抽屉、或需要滚动才能到达的历史区。  
**为何有害：** 每次跳转都打断用户的心流。迭代生成（调参数→重新生成）的频率极高，每次都跳转会产生累积摩擦。AetherGenix 当前：结果进任务抽屉，再出现在历史区（需要 2 次额外操作）。  
**如何修正：** 应用 Pattern 4（内联结果替换）。结果始终在配置面板旁边的结果区内更新。

> **归口例外（2026-05-31）：** 把「全量历史 / 失败任务 / 进行中任务 / 收藏」统一收口到独立的 `/assets` 资产库模块，**不属于本反模式**——这是低频的「资产管理」，而非高频的「结果查看」。判定标准按频率：高频对照（生成→挑一张回填→再生成）必须留在创作流内联（见 Pattern 4 的「最近结果」区），低频翻找与归档去 `/assets`。据此，原先挂在创作流右侧的独立历史栏与右上角任务抽屉应撤除，其职责分别下沉到「结果区内最近结果条」与「/assets 模块」。

---

### ❌ Anti-Pattern 3：上传无响应

**描述：** 用户上传图片后，UI 静止等待用户继续操作，没有任何系统反馈。  
**为何有害：** 违反 P-2 原则（上传即响应）。用户会怀疑上传是否成功，产生焦虑和不信任感。  
**如何修正：** 应用 Pattern 2（上传即响应）。上传完成后立即显示缩略图 + 开始后台分析。

---

### ❌ Anti-Pattern 4：纯色/渐变色模板缩略图

**描述：** 模板/风格选择器使用抽象色块或 CSS 渐变作为缩略图，而非真实效果图。  
**为何有害：** 用户无法从「深棕渐变」推断出「室内生活场景图」的实际效果，选择变成无意义的猜测。benchmark：Pebblely 的模板缩略图全部是真实商品合成效果图。  
**如何修正：** 为每个模板准备至少 1 张用真实商品生成的效果示例图，作为缩略图。

---

### ❌ Anti-Pattern 5：无阶段进度反馈

**描述：** AI 生成过程中仅显示一个 spinner 或旋转图标，无文字说明、无阶段划分。  
**为何有害：** 生成通常需要 10~60 秒，空白等待会让用户误判为系统卡死，导致提前放弃。benchmark：Adobe Firefly、豆绘AI 均有分阶段进度提示。  
**如何修正：** 应用 Pattern 6（GenerationProgress 组件），按垂类定制阶段文案。

---

### ❌ Anti-Pattern 6：默认全展开的高级选项

**描述：** 所有配置项（包括低频的材质描述、参考图上传、高级质量选项）默认全部可见。  
**为何有害：** 超过 5 个输入字段的表单会触发用户的"认知过载"反应，导致填写率下降和直接放弃。AetherGenix 电商页当前展示 7+ 个输入字段（含高级选项）。  
**如何修正：** 应用 Pattern 3（渐进式配置），只展示 1~2 个核心输入，其余折叠。

---

### ❌ Anti-Pattern 7：无「快速重试」路径

**描述：** 对生成结果不满意时，用户必须重新从头配置所有参数，才能再次生成。  
**为何有害：** 迭代是 AI 生图的核心使用模式，平均用户需要 3~5 次迭代才满意。每次迭代都重置状态，会成倍放大摩擦。  
**如何修正：** 结果图上提供「基于这张重试」按钮（保留所有参数，仅更换随机种子），以及「调整参数重试」（保留参数，直接在配置区修改，无需滚动回顶部）。

---

### ❌ Anti-Pattern 8：空状态只有文字说明

**描述：** 历史结果区为空时，显示「使用指南」文字、流程示意图，或仅有品牌 slogan。  
**为何有害：** 用户来是为了看效果，不是读说明书。空状态是建立信心的绝佳机会，用文字说明浪费了这个机会。  
**如何修正：** 应用 Pattern 5（空状态引导）。空状态必须展示真实 AI 生成效果图，视觉化地回答「这个工具能做什么」。

---

## 七、新垂类扩展 Checklist

> 每次开发新垂类页面（如：白底图、服装试穿、营销海报、室内效果图）时，  
> 在进入开发前执行此 Checklist。全部 ✅ 才可进入实施阶段。

### 📋 PRE-BUILD：设计阶段门卡

**范式选型**

- [ ] 已在「选型决策树」（第 2.2 节）中确认适用范式
- [ ] 已记录选型理由（用 1~2 句话说明为什么选这个范式）

**Step Budget**

- [ ] 已定义「快速路径」的最短操作步骤（≤ 第 4.2 节对应垂类目标）
- [ ] 已用手指点击模拟验证步骤数
- [ ] 快速路径中无任何非必要的「用户决策」

**结果展示**

- [ ] 已确定结果区位置（双栏右侧或单栏下方）
- [ ] 已准备 4~6 张「空状态示例图」（真实 AI 生成，不是设计稿）
- [ ] 生成结果将在当前页内联替换（不跳转、不进抽屉）

**反模式排查**

- [ ] 无表单驱动流程（配置项 ≤ 3 个默认可见）
- [ ] 上传图片后有 300ms 内的即时视觉响应
- [ ] 模板/风格选择器使用真实效果图缩略图
- [ ] 有分阶段进度组件（使用 GenerationProgress，定制阶段文案）

### 📋 POST-BUILD：验收阶段门卡

**功能验收**

- [ ] 在 Playwright 中录制从「打开页面」到「首张结果」的操作，确认步骤数符合目标
- [ ] 在移动端（375px）验证配置区可折叠，结果区生成后自动滚动到视口
- [ ] 「快速重试」（保留参数重新生成）可正常工作

**体验对标**

- [ ] 与同类范式的 benchmark 工具做并列对比（截图对比）
- [ ] 确认关键体感指标：上传响应 < 1s，生成进度有文字反馈，结果无需滚动即可看到
