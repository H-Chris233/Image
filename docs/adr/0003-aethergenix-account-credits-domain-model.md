# ADR 0003 · AetherGenix Account & Credits Domain Model

**状态**：已接受
**日期**：2026-05-18
**后续约束**：ADR 0004 · External Recharge Handoff Only

## 背景

AetherGenix 是面向普通用户的 AI 图像生成产品。后端通过 Sub2API 完成登录、注册、余额查询、托管 Key、生成代理和扣费。

普通用户不应该感知两套账户、两套余额或两套充值系统。对用户来说，他们只有一个 **AetherGenix 账户**，这个账户背后的身份、余额和充值来源由 Sub2API/统一账户服务提供。

上一版实现把账户、充值、账单、配置拆成多个入口，并把 Key、连接测试、上游系统、支付配置等工程概念暴露给普通用户。这会让用户误以为 AetherGenix 自己还有一套钱包、充值和财务管理。实际业务并不需要这些复杂度。

## 决策

### 1. 普通用户只理解 AetherGenix 账户

用户在 AetherGenix 登录时，后端实际调用 Sub2API 认证接口。Sub2API 用户映射为 AetherGenix 本地 owner：

- owner id：`user:<sub2api_user_id>`
- 登录 cookie：`aethergenix_session`
- 游客 cookie：`aethergenix_guest`

“Sub2API” 是管理员和运维需要理解的技术集成名词，不进入普通用户心智。

### 2. 唯一余额 source of truth 是 Sub2API

用户的可用余额、充值到账和生成扣费都以 Sub2API/统一账户服务为准。

AetherGenix 可以展示当前可用余额和本地生成摘要，但不自建独立钱包，不维护独立充值订单，不提供财务中心，也不让用户在两套余额之间切换。

### 3. 托管 Key 是服务端资产，普通用户不可见

登录成功后，AetherGenix 后端使用该用户在 Sub2API 下的托管 Key 调用 `/v1` 图像生成代理。如果用户没有可用 Key，后端可以在管理员凭证允许时自动创建。

普通用户不需要生成 Key、复制 Key、粘贴 Key、测试 Key，或理解 provider/auth URL。

### 4. 充值只做外部 handoff

充值入口只是把用户带到配置好的统一账户服务/充值页面。AetherGenix 站内不实现：

- 金额选择
- 支付方式选择
- 创建支付订单
- 二维码支付
- 订单轮询
- 充值订单列表
- 财务/账单中心

用户完成充值后回到 AetherGenix，刷新余额并继续生成图片。这个模式由 ADR 0004 固化。

### 5. 账户中心是轻量产品模块

普通用户账户中心只保留三个视图：

| 视图 | 用户问题 | 页面职责 |
|---|---|---|
| `/account` | 我是谁？还能不能生成？ | 展示登录身份、可用余额、最近生成摘要和少量动作入口 |
| `/recharge` | 怎么补充余额？ | 展示当前余额、刷新按钮、外部充值入口和继续创作 |
| `/config` | 我的偏好是什么？ | 展示资料、语言和公告偏好；管理员配置只对站主开放 |

`/billing` 只作为旧链接兼容，重定向到 `/account`。它不再是普通用户导航或财务中心。

### 6. 管理员和普通用户有明确词汇边界

普通用户界面允许出现：

- AetherGenix 账户
- 当前余额 / 可用额度
- 充值
- 刷新余额
- 创作历史
- 收藏
- 偏好设置
- 站点公告

普通用户界面不允许出现：

- Sub2API
- API Key
- 备用访问密钥
- provider base URL
- auth base URL
- `/v1/usage`
- 测试连接
- 上游系统
- 支付方式配置
- 订单/账单/财务中心

管理员配置页可以出现这些技术词，因为站主需要配置 Sub2API 实例、Admin API Key/JWT、试用额度、充值入口和公告。

## 被放弃的方案

- **AetherGenix 自建独立余额钱包**：会产生双余额、双充值和对账问题，当前业务不需要。
- **站内支付/订单/账单中心**：与实际业务脱钩；用户只需要在统一账户服务充值。
- **普通用户手动填写 API Key**：会把图像生成产品误导成开发者代理工具。
- **账户、充值、账单、配置作为多个顶级入口**：入口过多，会放大“多套体系”的错觉。
- **把 Sub2API 后台概念直接放进普通设置页**：实现成本低，但破坏产品心智。

## 影响

- 普通用户路径持续做技术词扫描，避免 Sub2API/API Key/支付配置回流。
- `/recharge` 永远是外部充值入口页，不承载站内 checkout。
- `/billing` 重定向到 `/account`。
- 管理员配置页是唯一展示 Sub2API 集成细节的位置。
- 回归测试需要覆盖：登录映射、托管 Key 不外露、余额展示、外部充值入口、普通用户词汇边界、管理员技术配置边界。

## 验证要求

- 未登录用户看到 AetherGenix 登录/注册和游客状态，不看到 Key 或 Sub2API。
- 已登录用户不需要手动配置 Key 也能生成图片。
- 已登录用户余额来自 Sub2API/统一账户服务，而不是本地钱包。
- 充值页只显示余额、刷新、外部充值入口和继续创作，不显示支付表单、订单或账单。
- 普通用户账户中心不出现技术词或财务管理入口。
- 管理员配置页可以配置 Sub2API base URLs、Admin API Key/JWT、试用额度和充值入口。

## 2026-05-18 最终收口

后续产品评审进一步收紧普通用户体验：AetherGenix 不再为普通用户维护独立的“充值页”和“设置页”视觉入口。

- `/account` 是普通用户唯一的账户与余额界面，负责显示登录身份、当前余额、刷新余额和外部充值入口。
- `/recharge` 仅作为旧链接兼容路由，直接重定向到 `/account`，不再单独同步余额。
- `/config` 对普通用户不可见；非管理员访问时重定向到 `/account`。
- 普通用户界面不再提供“继续创作”或“打开设置”类辅助入口；创作入口由全局导航承担。
- 管理员配置页仍保留 Sub2API 技术配置能力，但这属于站主工作台，不进入普通用户路径。
