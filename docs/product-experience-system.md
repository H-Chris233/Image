## 一、用户旅程图（User Journey Map）

### 人设：小李，淘宝店主
> 卖护肤品，日均发货 50 单，自己拍商品白底图，不懂 PS，想批量出场景图。

| 步骤 | 用户行为 | 当前 AetherGenix 体验 | 情绪 🌡 | 竞品对比 |
|------|---------|----------------------|--------|---------|
| **① 进入页面** | 看到什么？理解产品是什么？ | 看到标题"电商详情页设计" + 空白上传区 + 6 个渐变色缩略图 + 一堆表单 | 😐 困惑：「我应该先做什么？」 | Photoroom 首屏直接展示 6 个效果案例；Pebblely 展示 3 步图解 |
| **② 上传商品图** | 拖拽或点击上传 | 有效：虚线框可点击，支持拖拽，上传后显示缩略图 | 😊 顺畅，但没有上传后的确认感 | Remove.bg 上传即自动处理，有即时反馈 |
| **③ 选择风格模板** | 理解各模板的差异并选择 | 6 个渐变色块，名称：「室内生活」「户外自然」，**看不出实际效果差异** | 😟 茫然：「渐变色和我的商品有什么关系？」 | Pebblely 模板是真实场景照片，一眼就知道效果 |
| **④ 配置参数** | 填写商品名、材质、卖点等 | 7 个文本输入框全部展示，无必填标记，不知道哪些重要 | 😩 压迫感：「这么多要填，算了不填了」 | Photoroom 完全无表单；Firefly 用 Suggested Prompts 替代输入 |
| **⑤ 点击生成** | 点击按钮，等待结果 | 按钮变 spinner，**无其他反馈**，等待 20-60 秒不知道进度 | 😰 焦虑：「是不是卡住了？」 | Firefly 显示 3 阶段进度；Pebblely 有进度百分比 |
| **⑥ 看到结果** | 判断质量，决定是否使用 | 结果出现在页面下方历史记录区，需要滚动才能看到；4 张图缩略图很小 | 😕 费力：「结果在哪里？要点进去才能看大图？」 | Firefly 4 张大图并排在主视窗；Pebblely 结果页全屏展示 |
| **⑦ 迭代/出错** | 效果不满意，想调整重试 | 需要滚动回顶部，重新配置所有参数，**无快捷重试路径** | 😤 放弃：「太麻烦了，下次再说」 | Firefly "Refresh" 一键重试同参数；Pebblely 切换模板即触发重新生成 |

### 情绪曲线

```
情绪值（+高 / -低）
  +3 |              ②
  +2 |         ①         
  +1 |                    
   0 |——————————————————————→ 步骤
  -1 |                   ③④ 
  -2 |                        ⑤   
  -3 |                             ⑥⑦
```

**最大情绪断崖出现在：步骤 ⑤⑥⑦（生成中到看结果到迭代）**  
根本原因：**输入体验有改善（③④已部分优化），但输出体验（⑤⑥⑦）几乎未触碰。**

## 二、空状态设计规范

> 「空状态」是用户体验差距最大、修复成本最低的战场。

### 状态 1：首次进入（未上传图片）

| | 当前实现 | 问题 | 目标设计 |
|-|---------|------|---------|
| **内容** | 虚线框 + 图标 + "上传商品主图" | 无示例，用户不知道上传什么类型的图能得到什么效果 | 展示 6 张样例效果图（原商品白底图 → AI 场景图）横向排列在上传区下方 |
| **CTA** | 无明确引导文案 | | 加入引导文案：「上传你的商品白底图，AI 帮你生成场景图」 |
| **入门门槛** | 必须自己有商品图才能开始 | 新用户无法在上传前体验效果 | 增加「用示例商品体验」入口，点击后加载预置商品图进入流程 |

**推荐文案模板**：
```
[上传区标题] 上传商品图，生成电商场景图
[副文案]     支持 PNG / JPG，白底图效果最佳
[示例行]     效果参考：↓ 点击查看示例（展开 6 张样例）
[CTA]        或者，先用示例商品体验一下 →
```

---

### 状态 2：已上传图，生成前

| | 当前实现 | 问题 | 目标设计 |
|-|---------|------|---------|
| **视觉** | 上传区缩小为缩略图，表单全部展示 | 用户注意力被 7 个输入框分散，不知道下一步 | 上传成功后，高亮「下一步」区域（风格模板选择），其余区域降低对比度 |
| **引导** | 无"第一步"/"下一步"引导 | | 在风格模板上方加入：「第 2 步：选择场景风格」 |
| **AI 辅助** | AI 分析师（最重要功能！）在下方独立区块，容易被忽略 | 用户不知道有这个功能 | 上传图后 **自动触发** AI 分析，将分析结果作为参数预填充的依据，而非独立功能 |

---

### 状态 3：生成中（Loading）

| | 当前实现 | 问题 | 目标设计 |
|-|---------|------|---------|
| **视觉** | 生成按钮内 `<Loader2 animate-spin />` | 只有一个 spinner，20-60 秒等待无任何进度信息 | 3 阶段进度条 + 当前阶段文字说明 |
| **内容** | 无 | 用户不知道发生了什么 | 显示动态进度文字，示例：「正在分析商品特征（1/3）」→「正在构建场景（2/3）」→「正在精细渲染（3/3）」 |
| **逃生口** | 无取消按钮 | 如果用户想取消无法操作 | 加入「取消生成」次要按钮（样式：text-only，不抢主焦点） |

**进度阶段设计**：
```
[████████░░] 生成中 · 约 30 秒
正在分析商品特征…
Step 1/3 · 商品识别完成，开始构建场景
```

---

### 状态 4：生成成功（有结果）

| | 当前实现 | 问题 | 目标设计 |
|-|---------|------|---------|
| **展示位置** | 结果出现在页面下方历史区，需滚动 | 用户不知道结果出来了；缩略图小看不清 | 生成完成后，**自动滚动到结果区** + toast 通知「生成完成 ✓」 |
| **结果尺寸** | 历史卡片缩略图较小（约 120px） | 无法直观判断质量好坏 | 生成完成后展示 **当次结果大图模式**（4 张图 2×2 grid，每张 300px+） |
| **迭代路径** | 无快捷重试；需滚回顶部重配 | 放弃概率高 | 在结果卡片旁增加：「换个风格」「重新生成」「微调参数」三个快捷按钮 |
| **下载** | 历史卡片进入项目详情后有下载 | 路径深 | 每张结果图上浮现快捷「下载」按钮（hover 显示） |

---

### 状态 5：生成失败（Error）

| | 当前实现 | 问题 | 目标设计 |
|-|---------|------|---------|
| **错误提示** | 通用 toast 错误通知 | 用户不知道是什么原因失败，不知道怎么解决 | 分类型错误提示，每种配建议操作：网络超时（重试）/ 图片不符合要求（示例）/ 额度不足（升级引导）|
| **重试路径** | 无快捷重试 | 用户需要重新操作全流程 | 失败后在原生成按钮位置出现「重试」按钮，保持上次参数不变 |

---

### 状态 6：历史记录为空

| | 当前实现 | 问题 | 目标设计 |
|-|---------|------|---------|
| **内容** | `min-h-[260px]` 灰色区域 + 一行文字（`ecom_empty`） | 完全空洞，没有引导下一步 | 展示「精选效果展示」：官方制作的高质量示例图 4-6 张（带商品类型标签），点击某张可加载其参数 |
| **CTA** | 无 | | 加入：「生成你的第一张场景图 ↑」滚动到顶部 |

## 四、当前 /ecommerce 问题优先级列表

### 🔴 HIGH — 用户无法完成核心任务

| # | 问题 | 触发步骤 | 根因 |
|---|------|---------|------|
| H1 | **生成等待无反馈**：20-60 秒仅有 spinner，用户不知道进度 | 步骤⑤ | 缺少生成阶段反馈 |
| H2 | **结果不可见**：生成完成后结果在页面下方，需滚动，没有自动提示 | 步骤⑥ | 结果可发现性差 |
| H3 | **无快捷重试**：质量不满意需从头重配，迭代成本极高 | 步骤⑦ | 缺少结果页操作 |
| H4 | **空状态无示例**：首次进入无法预期效果，上传动力不足 | 步骤① | 缺少 onboarding 内容 |

### 🟠 MEDIUM — 用户完成困难，需多次尝试

| # | 问题 | 触发步骤 | 根因 |
|---|------|---------|------|
| M1 | **模板选择无直觉感**：渐变色块无法传达实际场景效果 | 步骤③ | 缩略图抽象，非真实场景 |
| M2 | **表单压迫感**：7 个文本框全部展示，无必填标记，门槛高 | 步骤④ | 缺少渐进披露 |
| M3 | **AI 分析师功能隐藏**：核心差异化功能在下方，用户不会发现 | 步骤② | 信息架构问题 |
| M4 | **错误提示无指导**：失败时用户不知道为什么、该怎么做 | 步骤⑦ | 错误反馈设计缺失 |
| M5 | **历史记录空状态单薄**：只有一行文字，无引导和灵感 | 步骤① | 空状态内容缺失 |

### 🟡 LOW — 体验可以更好，但不阻断任务

| # | 问题 | 触发步骤 | 根因 |
|---|------|---------|------|
| L1 | 格式选择用技术参数（"1:1"），而非平台场景（"主图 800×800"） | 步骤④ | 面向开发者思维 |
| L2 | 无"让 AI 帮我选"风格选项，必须主动选择 | 步骤③ | 缺少 AI 自动决策入口 |
| L3 | 可点击 Suggested Tags 缺失，文本框输入门槛高 | 步骤④ | 缺少引导输入 |
| L4 | 结果图展示尺寸小，无法在列表中判断质量 | 步骤⑥ | 历史卡片设计局限 |

## 五、改进蓝图（3 阶段实施）

### Phase 1 — Quick Wins（1-3 天，纯前端，零后端改动）

> 目标：让用户「至少能看到结果」的体验从 60 分提升到 75 分

#### QW-1：生成阶段进度反馈（解决 H1）
```
实现：在 handleSubmit 中，用 setInterval 模拟3阶段进度状态
组件：新建 <GenerationProgress> 替换 <Loader2>
文案：
  Stage 1（0-30%）：「正在识别商品特征…」
  Stage 2（30-75%）：「正在构建场景合成…」
  Stage 3（75-100%）：「正在精细渲染，即将完成…」
工作量：约 0.5 天
```

#### QW-2：生成完成自动滚动 + Toast（解决 H2）
```
实现：生成完成后 window.scrollTo({top: historySection.offsetTop}) + notifySuccess
Toast 文案：「✓ 生成完成！4 张场景图已就绪，向下查看」
工作量：约 0.5 天
```

#### QW-3：空状态样例图（解决 H4 + M5）
```
实现：
  - 上传区下方添加 6 张样例效果图横向滚动条
  - 历史空状态区域添加「精选效果展示」4 张示例
  - 所有样例来自设计团队制作，存放于 public/samples/
文案：「这些都是用 AetherGenix 生成的商品场景图 →」
工作量：约 1 天（含素材制作）
```

#### QW-4：FormatPicker 标签优化（解决 L1）
```
现状：主图 1:1 / 信息流 4:5 / 横幅 16:9 / 竖版 9:16
改为：主图（淘宝）/ 种草（小红书）/ 横图（详情页）/ 竖版（抖音）
每个标签下方保留技术参数作为次要信息
工作量：约 0.5 天（只改文案）
```

#### QW-5：必填字段标记（解决 M2）
```
实现：
  - productName 标记为「必填」（添加 * 标记和视觉区分）
  - 其余字段折叠至「高级选项」可展开折叠区
  - 展开时显示：「填写更多信息，AI 生成效果更好」
工作量：约 1 天
```

---

### Phase 2 — Core Flow（1-2 周，部分需轻量后端支持）

> 目标：让核心任务流从「能用」到「好用」，用户完成率目标 70%+

#### CF-1：结果大图展示模式（解决 H2 + L4）
```
设计：
  - 生成完成后，插入「本次生成」区块（优先级高于历史记录）
  - 4 张图以 2×2 大图 grid 展示（每张 280px+）
  - 每张图 hover 时浮现：下载 / 查看大图 / 「以此为基础重新生成」
  - 「本次生成」区块可折叠，之后并入历史记录
工作量：约 3 天
```

#### CF-2：结果页快捷重试（解决 H3）
```
设计：
  - 每个历史 ProjectCard 增加「快速重试」按钮
  - 点击：将该次生成的参数回填到顶部表单，用户直接改风格/数量后重新生成
  - 「换个风格」：在结果下方直接展示 6 个模板缩略图，点击即触发重新生成
工作量：约 2 天
```

#### CF-3：AI 分析师前置集成（解决 M3）
```
设计：
  - 上传商品图后，自动在后台触发 analyzeEcommerceProduct（不需用户手动点击）
  - 分析完成后：
    a. 高亮推荐的风格模板（AI 建议的模板加上「AI 推荐」标签）
    b. 自动预填 productName / style / scenarios（可编辑）
    c. 在表单顶部显示折叠提示：「AI 已为你推荐参数，可直接生成」
  - 原「AI 分析师」区块保留，用于展示推荐方案详情
工作量：约 3 天（改状态管理 + 触发时机）
```

#### CF-4：真实场景模板缩略图（解决 M1）
```
设计：
  - 替换 TemplatePicker 的渐变色为真实场景照片
  - 每张模板缩略图：场景照片 + 右下角商品占位区
  - 素材来源：可用已生成的高质量作品截图，也可购买正版场景图
  - 每张图 hover 时显示「适用场景」文字说明
工作量：约 2 天（前端 1 天 + 素材制作 1 天）
```

#### CF-5：错误恢复流程（解决 M4）
```
设计：
  - 失败 toast 从通用文案改为具体原因 + 建议操作：
    · 网络超时：「生成超时，可能是网络问题 → 点击重试（参数不变）」
    · 图片问题：「图片质量不足，建议使用白底商品图 → 查看示例」
    · 额度不足：「本月生成额度已用完 → 升级方案」
  - 生成按钮区域在失败后显示内联重试选项
工作量：约 1 天
```

### Phase 3 — Advanced UX（2-4 周，需产品+后端协作）

> 目标：从「好用」到「上瘾」，打造差异化的 AI 协作体验

#### AX-1：示例商品 Onboarding（「先体验，再上传」）
```
设计：
  - 首次进入页面，展示「试用演示商品」入口
  - 预置 4 个演示商品：数码、美妆、食品、家居
  - 点击即加载对应商品图和推荐参数，直接可生成
  - 看到效果后出现 CTA：「上传你自己的商品图」
价值：解决「不知道效果 → 不敢上传」的初次使用断层
工作量：约 3 天（素材 + 逻辑）
```

#### AX-2：一键出图（极简路径）
```
设计：
  - 新增「快速出图」模式：上传商品图 → AI 自动选最优场景 → 直接生成
  - 整个流程用户只需做 1 个决策（上传图片）
  - 结果出来后提供「切换风格」「精细调整」入口
价值：对应 Remove.bg 的「零配置首跑」，留住最懒的用户
工作量：约 4 天（AI 推荐逻辑 + 简化界面）
```

#### AX-3：批量商品处理
```
设计：
  - 支持一次上传多张商品图（最多 10 张）
  - 同一场景设置应用到所有商品，批量生成
  - 结果以每个商品为单位整理，支持批量下载
价值：运营商家核心需求：同款多颜色 / 多款同风格批量出图
工作量：约 5 天（UI + API 扩展）
```

#### AX-4：生成结果 AB 对比模式
```
设计：
  - 支持将同一商品的两次不同风格生成结果并排对比
  - 横向滑动对比（类似 Remove.bg 的 before/after）
  - 方便商家快速决策「用哪个版本发布」
工作量：约 3 天
```

## 七、核心设计原则（为 AetherGenix 电商工作台定制）

| 原则 | 描述 | 反例 |
|------|------|------|
| **结果优先** | 用户在 30 秒内看到价值，配置是辅助 | 现在：先填 7 个框才能看到结果 |
| **AI 做决定，人来审核** | 所有参数都有 AI 默认值，用户只需要确认或修改 | 现在：所有字段都等用户填 |
| **失败是流程的一部分** | 生成失败 / 质量差 应有清晰的恢复路径，而非终点 | 现在：失败后用户面对 toast 和空白 |
| **展示即说明** | 所有能用图片说明的地方，不用文字（模板、示例、教程） | 现在：渐变色块 + 文字描述 |
| **运营思维，不是设计思维** | 目标是「可发布的图」，不是「漂亮的图」 | 纯美学优化 vs 商家实用性优化 |
